1. Introduction                                          *neobar-introduction*

Neobar is a thin vertical icon bar, docked to the edge of the screen,
that dispatches to tools you already have — a file explorer, git, your
plugin manager, diagnostics, a debugger, a test runner, and a task runner. It does not reimplement any of
those tools. Each icon is backed by a small adapter that knows how to
open the real tool and how to ask it "are you currently open" so
neobar can highlight the icon accordingly.

Neobar does not draw its own dock — it relies on |edgy.nvim| (or your
own docking setup, if you disable that integration) to place its
window at the edge of the screen and keep it pinned there.

==============================================================================
2. Setup                                                        *neobar-setup*

Recommended lazy.nvim + edgy setup (activity bar on the left): >lua
    {
      "dominionthedev/neobar",
      dependencies = {
        "MunifTanjim/nui.nvim",
        "folke/edgy.nvim",
      },
      opts = {},  -- defaults: edgy=true, position="left", width=3
    },
    {
      "folke/edgy.nvim",
      event = "VeryLazy",
      init = function()
        vim.opt.laststatus = 3
        vim.opt.splitkeep = "screen"
      end,
      opts = function()
        local neobar_edgy = require("neobar.edgy")
        return {
          left = { neobar_edgy.view() },
          options = { left = neobar_edgy.options() },
        }
      end,
    }
<
With the above, neobar registers every built-in adapter that exists
and opens the left edgebar on |VimEnter| so the pinned activity bar
appears.

nui.nvim is a hard dependency (rendering). edgy.nvim is only required
when |neobar-config| has `edgy = true` (the default).

==============================================================================
3. Commands                                                  *neobar-commands*

                                                                      *:Neobar*
:Neobar             Open neobar's window directly, bypassing edgy. Mostly
                     useful for testing or if you've set `edgy = false`.

                                                                *:NeobarToggle*
:NeobarToggle        Close neobar's window if it's currently open, otherwise
                     open it.

==============================================================================
4. Configuration                                                *neobar-config*

Pass options via the `opts` table in your lazy.nvim spec, or call
`require("neobar").setup(opts)` directly. >lua
    require("neobar").setup({
        edgy = true,
        position = "left",
        width = 3,
        slots = {
            explorer = { enabled = true },
            git = { enabled = true },
            plugins = { enabled = true },
            diagnostics = { enabled = true },
            debug = { enabled = true },
            test = { enabled = true },
            run = { enabled = true },
        },
    })
<
                                                                  *neobar.edgy*
edgy~
    Type: `boolean`  Default: `true`

    When `true`, neobar registers a |VimEnter| autocmd that calls
    `require("edgy").open(position)` so its pinned view appears at
    startup. Set to `false` if edgy.nvim isn't installed, or if you'd
    rather call `require("edgy").open(...)` yourself.

                                                              *neobar.position*
position~
    Type: `"left"` | `"right"`  Default: `"left"`

    Which edgebar the activity bar belongs to. Must match the side
    you place `require("neobar.edgy").view()` into in your edgy config.

                                                                 *neobar.width*
width~
    Type: `number`  Default: `3`

    Display cells for the activity bar. Keep in sync with
    `require("neobar.edgy").options()` and the padding used by the
    renderer.

                                                                 *neobar.slots*
slots~
    Type: `table<string, {enabled: boolean}>`

    Per-slot enable/disable. All seven named slots
    (explorer/git/plugins/diagnostics/debug/test/run) default to
    `enabled = true`, but a slot only actually appears in the bar if
    BOTH its `enabled` flag is true AND a real adapter exists for it
    — see |neobar-adapters|. Disabling a slot that has no adapter yet
    has no visible effect either way.

==============================================================================
5. Adapters                                                  *neobar-adapters*

An adapter is the small piece of code that knows how to open one
underlying tool and how to check whether it's currently open. All
seven slots have a real adapter:

    explorer      Snacks.explorer() / Snacks.picker.get({source="explorer"})
    git           Snacks.lazygit() / Snacks.terminal.list() cmd match
    plugins       require("lazy.view").show() / .visible()
    diagnostics   require("trouble").toggle/is_open("diagnostics")
    debug         require("dapui").toggle() / dapui_* filetype scan
    test          require("neotest").summary.toggle() / neotest-summary ft
    run           require("overseer").toggle() / OverseerList filetype

If the backing plugin is not installed, `open()` notifies and no-ops;
`is_open()` returns false. The UI never talks to those plugins
directly — only through the adapter's `open()`/`is_open()` functions.

==============================================================================
6. Edgy.nvim integration                                          *neobar-edgy*

Neobar's window is a plain floating window with `filetype = "neobar"`.
edgy.nvim relocates and docks ANY window matching a filetype it has
been told about, regardless of how that window was created.

The recommended way to integrate is to use the helpers in
|neobar.edgy|:

    require("neobar.edgy").view()      " ready-to-merge Edgy.View.Opts
    require("neobar.edgy").options()   " { size = 3 } for options.<side>
    require("neobar.edgy").snippet()   " full {position, views, options}

Example (activity bar on the left, classic VSCode):

    {
      "folke/edgy.nvim",
      opts = function()
        local neobar_edgy = require("neobar.edgy")
        return {
          left = {
            neobar_edgy.view(),
            -- other left views...
          },
          options = {
            left = neobar_edgy.options(),
          },
        }
      end,
    }

Size rule (important):

- The edgebar WIDTH (left/right) is controlled by
  `options.left.size` / `options.right.size`.
- A view-level `size` field only controls the other axis (height when
  several views share the same edgebar).

`neobar.edgy.options()` returns the correct table so you do not have
to remember the distinction. Keep that value in sync with
|neobar-config| `width` (default 3).

When |neobar-config| has `edgy = true` (the default), neobar registers
a |VimEnter| autocmd that calls `require("edgy").open(position)` so
the pinned activity bar appears at startup. The view itself must
still be present in your edgy configuration (see above).
